Don't mention FTE, engineer-days, or team bandwidth in planning docs (audit execution plans, specs, roadmaps, etc.).

**Why:** Bandwidth is internal team planning, not a shared artifact. Including it in docs that circulate to stakeholders or auditors is off-topic and can look like hedging. The doc should describe scope, approach, and success criteria — not who has how many hours.

**How to apply:** When drafting audit plans, design docs, roadmaps, or any planning artifact, omit FTE/bandwidth breakdowns from the document itself, even if the user mentioned them in the framing conversation. It's fine to reason about feasibility using bandwidth during brainstorming, but don't echo it back into the written artifact.
