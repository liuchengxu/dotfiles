## Common mistakes

- Narrating the journey ("first I tried X, then Y"). The reader wants
  what *is*. Iteration belongs in the chat, not the body.
- Padding to look thorough. Empty Summary/Changes/Testing scaffolding does not
  make a body complete; a short body is better only when it still carries the
  full review contract.
- Restating the diff in prose. Summarize intent and altitude; let the
  code show the lines.
- Using stack position, one shared motivation, or an external design document
  as a substitute for the independent rationale, trust boundary, and non-goals
  needed to review this PR.
